## Scope delivered

| Area | What exists now (`packages/domain/src`) |
|---|---|
| Calendar | `civ365-daily-v1`: 1 tick = 1 day in 365-day years. For 1–2026 CE, `endTick` = 739,490. `instantAt`, `firstTickOfYear` and `isConsistentInstant` map between ticks and calendar dates. |
| Schedule | `ticksDueAt` and `dueAtMs` map real time to due ticks with BigInt arithmetic from the origin, so there is no drift. `SEASON_DURATION_MS` = 720 h. |
| Hashing | Pure-TypeScript SHA-256 and `canonicalHash` (RFC 8785 → `sha256:`). |
| PRNG | `RandomRoot.stream(...path)` and `split(...)`. Each stream runs xoshiro128**, keyed by SHA-256 of its label path. The API is integer-only: `nextUint32`, `nextInt` (unbiased), `chance`, `weightedIndex`, `pick`, `shuffled`. |
| IDs | `deriveId(kind, ...scope)`: 80 bits of SHA-256 encoded as 16 base-36 characters. |
| Units | Arithmetic on safe integers with `UnitOverflowError`. `mulDiv`, `divide`, `applyPpm` and `convert` take one of six explicit rounding modes. `allocate` uses largest-remainder conservation. Quantities carry units and dimensions. |
| Systems | `createSystemSchedule`: explicit unique `order`, cadences (`DAILY`, `YEARLY`, custom), and a config descriptor. |
| Kernel | `createEngine().apply` is a pure command → events/state transition covering `world.pause`, `world.resume` and `world.advance`. It provides: <ul><li>typed rejections;</li><li>events with derived IDs and contiguous sequences;</li><li>versions bound into every event;</li><li>world data frozen and JSON-validated;</li><li>`maxTicksPerAdvance` (default 3,650);</li><li>`world.*` event types reserved for the kernel;</li><li>`replay` and `checkpoint`.</li></ul> |
| Contracts | `world.advance` command (system or operator actor) and `world.advanced` event, with frozen fixtures (calendar-consistent instants) and regenerated JSON Schemas. |
| Lint guard | The domain also bans:<ul><li>`Intl`, locale methods;</li><li>`Math` functions that are not bit-exact, `**`;</li><li>host globals (`globalThis`…), GC-timing APIs, `queueMicrotask`/`setImmediate`, `require`;</li><li>dynamic `import()`, aliasing or computed access of `Math`;</li><li>all Node built-in modules.</li></ul> |
| Bench | `pnpm --filter @civ/domain bench` (`packages/domain/bench/kernel.bench.mjs`). |
| Docs | `docs/KERNEL.md`, `docs/adr/0004-deterministic-kernel.md`. |

## Acceptance mapping

| Criterion | Evidence | Result |
|---|---|---|
| Repeated runs on supported platforms produce identical canonical event/state hashes | `kernel.test.ts` freezes golden config, event and state hashes, the checkpoint and the resulting data for a scripted 4,397-tick scenario. `random.test.ts` and `ids.test.ts` freeze golden PRNG and ID values. Golden values are never rewritten under `CI=true`. A cross-platform probe (a full 739,490-tick season with two random systems, 203 batched commands) gave identical PRNG draws, ID, state hash and event hash on: <ul><li>darwin-arm64, Node 22.19.0;</li><li>linux-arm64, Node 22.23.3;</li><li>linux-arm64, Node 24.21.0.</li></ul> | PASS (x64 is covered by CI goldens once pushed) |
| Draws in one named stream do not perturb another | Property test: 0–500 extra draws in `births` leave `deaths` identical. `split` children are independent of how much the parent drew. In the kernel, `harvest` drawing 9× instead of 1× leaves `census` and `weather` data identical. | PASS |
| Year 1 starts and year 2026 completes at defined boundaries | Tick 0 is year 1, day 1. Tick 364 is year 1, day 365, and tick 365 is year 2, day 1. Tick 739,489 is year 2026, day 365. Position 739,490 means complete (year 2027, day 1). Positions outside the range throw. A property test round-trips every tick. The schedule makes 0 ticks due at the start and all due exactly at the end, with each year boundary at an exact instant. | PASS |
| 30-day schedule cannot drift | `dueAtMs`/`ticksDueAt` are inverses (property test). They are monotonic for arbitrary schedules. The midpoint (tick 369,745) is due exactly at start + 360 h. Hourly pace is ⌊739,490/720⌋. | PASS |
| Unit overflow and rounding behaviour specified and tested | `docs/KERNEL.md` has the rounding table. The units tests cover:<ul><li>the full rounding-mode table at ±0.5 and ±1.5;</li><li>property checks against exact rational bounds;</li><li>overflow at ±(2^53 − 1) for add/sub/mul/mulDiv/convert;</li><li>exact BigInt intermediates;</li><li>`allocate` conservation (property);</li><li>no cross-dimension conversion.</li></ul> | PASS |
| Ban ambient randomness, wall clock, locale sorting and network/DB in domain code | ESLint rules are proven by `tests/tooling.test.mjs` with 20 bypass and usage cases. `arch:check` enforces the dependency policy. | PASS |
| Pure command→event/state scaffolding | `kernel.test.ts`:<ul><li>every rejection code is exercised and none mutates state;</li><li>the input state is unchanged after `replay`;</li><li>a mutating-then-throwing system leaves the input hash unchanged;</li><li>non-JSON data and reserved or unregistered events throw.</li></ul> | PASS |
| Deterministic fixtures: same-seed equality, stream isolation, seed divergence, calendar boundaries, serialization ordering, checkpoint hash stability | All are covered by the tests above. Serialization order is checked by key-reordered state giving the same hash and checkpoint. | PASS |
| Gates pass | `CI=true pnpm gates` exits 0 (see below). | PASS |

## Independent review

The review was done by an independent read-only subagent (Sonnet) acting as the project `reviewer`. It found no Critical or High issues, and confirmed correct:

- SHA-256 padding;
- the xoshiro step;
- `nextInt` rejection sampling;
- unambiguous label encoding;
- disjoint namespaces;
- schedule and calendar boundaries;
- rounding;
- that rejections have no effects;
- calendar-consistent new fixtures.

| # | Severity | Finding | Disposition |
|---|---|---|---|
| 1 | Medium | Kernel does not dedupe by idempotency key (a re-delivered pause can re-pause after a resume) | Deduplication belongs to the command log's unique (world, idempotencyKey) constraint (Phase 03); an unbounded key set in state would grow forever. Documented in KERNEL.md and ADR 0004 §13. `advance` is self-guarding via `fromTick` |
| 2 | Medium | Unbounded single advance | Fixed: `maxTicksPerAdvance` (default 3,650, in the config digest) and `too_many_ticks`; test |
| 3 | Medium | Purity depends on systems not mutating input | Fixed: incremental deep-freeze of world data at creation and after each run; test that a mutate-then-throw system leaves the input hash unchanged |
| 4 | Medium | Bad system output thrown late or forged control events | Fixed: data is JSON-validated as it is frozen (`WorldDataError` with path); `world.*` drafts from systems throw; when `apply` throws is documented; tests |
| 5 | Low | Lint bypasses (`globalThis.Date`, destructured or aliased `Math`, `Math["pow"]`, dynamic import, other globals and modules) | Fixed; 9 new lint test cases |
| 6 | Low | `clockPosition` has no upper bound | No change: Zod 4 `.int()` already limits values to safe integers |
| 7 | Low | Schedule subtraction in Number before BigInt | Fixed: BigInt subtraction plus a safe-duration assertion |
| 8 | Low | New fixtures stamp engine 0.1.0 while the engine is 0.2.0 | Accepted: fixtures are contract examples and are not tied to the engine version |

The fixes were followed by the full gate run above. Golden snapshots changed once, deliberately: `maxTicksPerAdvance` joined the config document, so `configVersion` and the event hash changed. The state hash and the simulated data were unchanged.

## Compatibility, migrations, rollout and rollback

- No database migration. No persisted worlds or events exist yet, so the engine bump to 0.2.0 has no data to migrate.
