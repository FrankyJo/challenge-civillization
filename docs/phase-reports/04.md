## Scope delivered

| Area | What exists now |
|---|---|
| **Generator** (`@civ/domain`) | `generateWorldMap({ worldId, seed, params })`, integer-only and seeded by named streams. It builds terrain, elevation, water (one ocean plus depression lakes), drainage and rivers, temperature, precipitation, climate classes and latitude bands, biomes, land cover, arable potential, timber, fish, seven minerals, four hazards, landmasses and regions. It validates its own output. `mapVersionOf` gives the map version, and `DEFAULT_MAP_PARAMS` is 80 × 60 cells of 5 km. |
| **Validation** | `validateWorldMap` and `assertValidWorldMap` check: <ul><li>structure, hash and version;</li><li>grid, projection and latitude bands;</li><li>water/land consistency and landform;</li><li>the connectedness policy;</li><li>the region partition;</li><li>drainage acyclicity and discharge conservation;</li><li>resource and hazard bounds;</li><li>deposits, impossible coordinates and the land share.</li></ul> |
| **Spatial** | Cell index, reversible `cel_` spatial IDs, axial distance, neighbours, `cellsWithin`, `cellAtPoint`, cell centres in metres, and `ImpossibleCoordinateError`. |
| **Routes** | Data-driven `TravelProfile` (`FOOT_TRAVEL`, `FOOT_AND_BOAT_TRAVEL`), symmetric integer edge minutes, A* `findRoute` (optional `maxMinutes`), and multi-source `travelField`. |
| **Capacity inputs** | `capacityInputs` and `regionCapacityInputs`: integer land, cover, arable potential, timber, water, fish, climate means and deposits. |
| **Public projection** | `mapSnapshot` produces the `public-map-snapshot` (25 KiB), and `decodeRegionRuns` decodes its region runs. |
| **Engine** | `createEngine({ geography: { mapVersion, mapHash } })` adds the map identity to the config document, and so to `configVersion`. |
| **Storage** (`@civ/db`, migration 0004) | `civ.world_maps` is append-only, with CHECK constraints tying both documents to the row. <ul><li>`createWorld({ map })` stores the map in the world's creation transaction.</li><li>`verifyWorldMap` recomputes the hash with `node:crypto`.</li><li>`loadWorldMap` reads and verifies the map.</li><li>`readMapSnapshot` reads only the snapshot column.</li></ul> |
| **Simulation app** | `prepareGeography` generates the map, snapshot, reference and stats. `loadGeography(pool, worldId, expected)` validates, binds the map to the engine, checks the snapshot projection and regenerates the map. |
| **Contracts** | Three contracts, each with a frozen fixture (a real 10 × 8 generator output) and a JSON Schema. |
| **Tooling** | <ul><li>`pnpm --filter @civ/domain bench:map` measures the budget and fails if the default map exceeds it.</li><li>`bench/map-preview.mjs` renders a PNG for review.</li></ul> |
| **Docs** | `docs/GEOGRAPHY.md` and `docs/adr/0006-generated-hex-geography.md` are new. KERNEL, CONTRACTS, PERSISTENCE, ARCHITECTURE and README are updated. |

## Independent review

A `reviewer` subagent (Sonnet) reviewed the diff and ran the domain tests. It also fuzzed `cellsWithin` against a brute-force filter and `cellAtPoint` against 20k points; both had 0 mismatches. It confirmed:
- A* is admissible and consistent;
- edge costs are symmetric;
- generation has no float or ordering hazards;
- the snapshot leaks nothing;
- the down migration refuses with data present.

It found 0 critical, 0 high, 4 medium and 7 low findings. All were addressed:

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | Medium | `regionRuns` accepted negative or huge runs whose total matched, so a decode could exhaust memory. | The schema bounds the values and the length, and requires runs ≥ 1 and region indices in range. `decodeRegionRuns` re-checks. Contract tests cover crafted runs. |
| 2 | Medium | Nothing proved the stored snapshot is the projection of the document. | `loadGeography` compares `mapSnapshot(document)` with the stored snapshot. |
| 3 | Medium | The validator missed fish bounds, deposit totals overflowing 2^53, terrain vs elevation, and band vs latitude. | Shared classification rules (`classify.ts`) are recomputed by the validator: landform, climate band and fish bounds. Discharge, runoff, fish and timber are capped at ≤ 10¹⁵, and deposits at ≤ 10⁹ t. The unchecked cover split is documented. Three new corruption tests. |
| 4 | Medium | Nothing bound the stored map to the engine config. | `loadGeography` now **requires** the engine's map reference. |
| 5 | Low | The shared topology cache is mutable. | It is no longer exported from the package index, and is documented as read-only and internal. |
| 6 | Low | The `travelField` tie rule was documented wrongly and region growth was untested. | The comment and spec now state the real rule. A property test checks determinism, contiguity and nearest-source costs. |
| 7 | Low | The land-share tolerance had no rationale. | It is documented as an empirical envelope backed by the sweep and the property test. |
| 8 | Low | Travel speeds were presented as fact. | They are labelled uncalibrated defaults. |
| 9 | Low | A version bump was not enforced when golden values changed. | The test freezes `MAP_GENERATOR` next to the hashes. |
| 10 | Low | No SQL check tied `worldId`. | CHECK constraints tie the document and snapshot `worldId` to the row. |
| 11 | Low | The `cellsWithin` and `cellAtPoint` tests were weak. | Brute-force equivalence properties replace them. |

After the fixes, the full gate is green (above) and the golden hashes are unchanged: the fixes did not alter generator output.

## Compatibility, rollout and rollback

- **Migration 0004** only creates a new table, so it takes no lock on existing data and rewrites nothing. Existing worlds have no map row and keep working. `loadWorldMap` reports `NotFoundError` for them, and `readMapSnapshot` returns `null`.
- **Engine.** `geography` is optional. Configs without it hash exactly as before, so the golden kernel hashes are unchanged and Phase 03 worlds replay identically.
- **Rollout.** Deploy the migration, then the code. Worlds created from now on can store a map. The runner (Phase 06) will launch worlds with `prepareGeography` and load them with `loadGeography`.
- **Rollback.**
  - `0004 down` refuses once any map is stored (SQLSTATE 55000); production rolls forward.
  - Rolling the code back to Phase 03 leaves the table unused and harmless.
  - A stored map is the launch record and is never regenerated in place.
- **Generator changes.** Bump `MAP_GENERATOR.version`. Existing worlds keep their stored documents, and reproduction is checked only for maps of the running version.
