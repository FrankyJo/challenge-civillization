# Phase 05 report: cultures, names and the 10,000-person seed

- **Status: passed.** All acceptance gates are green. Caveats are listed under Remaining risks.
- **Commit:** an uncommitted working tree on branch `claude/phase-05`, based on `140c02e` (Phase 04 on `main`, pushed; GitHub CI `quality` passed on PostgreSQL 17).
- **Date and environment:** 2026-11-21; macOS arm64 (Apple M1 Pro); Node 22.19.0; pnpm 10.33.0. The gate ran against a disposable host PostgreSQL 16.11 (`fsync=off`) and Redis 8, because Docker PostgreSQL 17 on this machine has very high latency (Phase 04 report).
- **Versions:**
  - engine `0.2.0`, unchanged;
  - content pack `civ.season_one@1.0.0`;
  - map generator `civ-hexgen@1.0.0`, unchanged;
  - population generator `civ-popgen@1.0.0`;
  - DB migration head `0005`;
  - new contracts `content-pack@1`, `seed-population@1` and `world-data@1`;
  - new ID kinds `person` (`per`), `household` (`hhd`) and `settlement` (`stl`).
- **Product decision.** The user chose fictional cultures with constructed-language names, authored and CC0, over real attested names (ADR 0007).

## Acceptance mapping

| Criterion | Evidence | Result |
|---|---|---|
| Exact living count of 10,000 | <ul><li>The golden test asserts 10,000.</li><li>A property test with 20 runs over sizes 1–400 and 5–12 settlements fills every size exactly.</li><li>The audit compares the count with `params.size`.</li><li>A database CHECK requires `living` to equal the stored persons.</li><li>`launchWorld` stores 10,000.</li></ul> | PASS |
| No impossible parent ages or times | The audit requires: <ul><li>mother aged 13–50 and father 14–80 at birth, parent born before child, right sex;</li><li>births at least 270 days apart per mother, or up to 3 multiples on one day;</li><li>recorded parents who are each other's partners;</li><li>siblings of a head at least 270 days apart.</li></ul> Corruption tests cover a 5-year-old mother, a mother younger than her child, births 100 days apart and non-partner parents. | PASS |
| No duplicate identity IDs | IDs are derived from (world, settlement, household, member). The audit checks the uniqueness of person, household and settlement IDs; a duplicate-ID corruption test covers this. | PASS |
| No missing guardianship states | <ul><li>Every dependent (under the adult age) has a guardian of kind parent, kin or foster; adults have none.</li><li>The guardian is co-resident and not a dependent.</li><li>A parent guardian is that parent; a parent is never a kin or foster guardian; a grandparent is at least 30 years older.</li><li>Nobody marries before adulthood (contract and audit).</li></ul> Tests cover a removed guardian, a guardian in another household and a married minor. | PASS |
| No invalid household or location references | <ul><li>Households partition people, with the head first and one settlement each.</li><li>Each person's household, settlement, cell and culture agree.</li><li>Settlements sit on land in a region of their culture.</li><li>Household roles match kinship.</li></ul> Corruption tests cover a bad household, a bad cell and a contradictory role. | PASS |
| No out-of-era names | <ul><li>Entries carry era intervals; 15% are archaic and 15% start in 60–360 CE.</li><li>The sampler filters by birth year.</li><li>Shared names of unrecorded relatives are valid for every bearer's year.</li><li>The audit checks every dataset part against the bearer's birth year.</li></ul> An out-of-era corruption test covers this. | PASS |
| Every name records its dataset, version and fallback | <ul><li>Each part carries `{ dataset, version, entryId, fallbackLevel }`, a derivation from a relative (with a dataset base if the relative is unrecorded), or the settlement.</li><li>The audit resolves entries and checks that no earlier dataset in the chain was eligible.</li></ul> Velani settlements are named at fallback level 1 (Velan has no place names). Tests cover a wrong fallback level, a broken patronymic and divergent sibling bases. | PASS |
| Same seed reproduces the population hash | <ul><li>The golden hash is frozen; `POPULATION_GENERATOR` is frozen next to it.</li><li>Repeated synthesis gives the same hash, and another seed diverges.</li><li>`loadSeedPopulation` re-synthesizes and compares on load (integration test).</li><li>All randomness comes from named streams; the arithmetic is integer.</li></ul> | PASS |
| Distribution reports are plausible and reviewed | <ul><li>The report and 9 plausibility checks pass for the golden seed, two test seeds and nine more seeds in a sweep.</li><li>The values and their deviations are reviewed in `docs/POPULATION.md`, including household size ≈ 3.2 and 65+ ≈ 1.3%.</li><li>The independent review covered the population.</li></ul> | PASS, with documented deviations |

## Independent review

A `reviewer` subagent (Sonnet) read the diff, ran the domain unit tests and scanned 5 seeds with a throwaway script. It found 1 high, 4 medium and 3 low findings. All were addressed:

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | High | A stem household could overwrite a pooled head's recorded parents, so a person had a mother and father from different households (6–14 per seed). | A pooled head keeps a nuclear household. The audit requires both recorded parents to be partners; a regression test covers it. |
| 2 | Medium | Children of a widowed parent got different names for the same unrecorded parent and lost sibling name uniqueness. | Children of one marriage share a lineage. Unrecorded-relative names are keyed by the recorded other parent across households. The audit checks that siblings agree; a test covers it. |
| 3 | Medium | Married minors: brides of 14, with marriage emancipating guardianship. | Nobody marries before the adult age (pack minimum 15, a contract refinement and an audit check). The dependent definition is now age only. A test covers it. |
| 4 | Medium | The validator did not check roles against kinship, guardian relation semantics or foster/parent confusion. | Added checks: spouse, child, parent, grandchild, fosterling and sibling against kinship; a parent never a kin or foster guardian; grandparent age gap. A test covers it. |
| 5 | Medium | The `kin_care` form and fostering semantics were unclear. | Documented in the contract and the spec: the `kin_care` weight covers orphan care, and foster placements are labelled nuclear. |
| 6 | Low | A possibly stale leaver reference after trimming, and a silent missing head. | Documented the invariant; a missing head now throws. |
| 7 | Low | Calibration wording ("typical"). | The pack and docs say "chosen defaults screened for plausibility, not fitted". |
| 8 | Low | Gender categories assigned at random; the ordering under-represented later categories. | One draw over cumulative prevalences. Documented as a modelling placeholder. |

After the fixes, the golden hash was re-frozen. The three uncommitted fixtures were regenerated: never released, removed from and re-added to the manifest. The full gate is green.

## Compatibility, rollout and rollback

- **Migration 0005** only creates a new table, with no lock on existing data. Worlds without a population keep working, and `loadWorldPopulation` reports `NotFoundError` for them.
- **Contracts.** The new contracts and ID kinds are additive. `createWorld` accepts optional `population` input; existing callers are unchanged.
- **Engine.** The engine is unchanged; the world data contract is new. Season-one worlds now have `contentVersion = contentVersionOf([civ.season_one])` instead of a placeholder digest.
- **Rollback.**
  - `0005 down` refuses once any population is stored (SQLSTATE 55000); production rolls forward.
  - Rolling the code back to Phase 04 leaves the table unused.
- **Generator or content changes.** Bump `POPULATION_GENERATOR.version` or the pack version. Stored worlds keep their populations, and reproduction is checked only for the running version.
