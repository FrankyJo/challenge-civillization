# ADR 0003: Executable contracts and dependency boundaries

- Status: Accepted
- Date: 2026-11-20

## Context

Phase 01 requires the following, without inventing domain events that later phases have not specified:

- versioned schemas for world and season metadata, simulation instants, command and event envelopes, versions, cursors and checkpoints, API errors, and proposal/source/review states;
- canonical serialization and stable IDs;
- frozen compatibility fixtures;
- public DTO allowlists;
- generated schema documentation;
- architecture tests.

## Decisions

1. **Zod 4 strict objects are the single source of truth.** TypeScript types are inferred from the schemas. JSON Schema is generated by `z.toJSONSchema` and byte-checked in tests. There is no separate IDL.
2. **One envelope mechanism plus registries.** The envelope carries every audit field: world, instant, causation, correlation, versions and payload type/version; commands also carry an idempotency key, actor and expected version. Registries resolve `type@typeVersion` to a strict payload schema. Unknown types, versions and fields are rejected, and parsing produces a TypeScript tagged union. Old `typeVersion`s stay registered; there are no upcasters until a phase needs one.
3. **Events carry no wall-clock time.** `issuedAt` exists only on commands, as recorded external input. Events must replay byte for byte.
4. **The only example variants are world pause/resume** (commands `world.pause`/`world.resume`, events `world.paused`/`world.resumed`), because `docs/SECURITY-OPERATIONS.md` specifies them as operator controls with reason text and an audit event. The behaviour behind them arrives with the runner (Phase 06) and admin (Phase 21).
5. **RFC 8785 (JCS) canonical JSON, implemented in-house** in about 100 lines. It is stricter than JCS in that it rejects `undefined`, sparse arrays, non-plain objects and lone surrogates instead of coercing them. Hashing is left to Phase 02, so `@civ/contracts` stays browser-safe.
6. **Prefixed stable IDs** (`wld_…`, `evt_…`) with branded types; the prefixes are a permanent format. The body is `[0-9a-z]{8,64}`, leaving generation strategy to Phase 02.
7. **Frozen fixtures with a checksum manifest.** Fixture bytes are immutable, which is enforced by test. Every catalogued contract and registered variant must have one.
8. **Public DTOs are allowlists derived from internal shapes** (`definePublicDto`). Nothing reaches a public schema unless named.
9. **The API returns the `ApiError` contract for every error.** Client errors get stable codes with generic text; 5xx errors are logged and never exposed.
10. **A dependency policy enforced by an import-graph checker** (`scripts/architecture-policy.mjs`, `scripts/check-architecture.mjs`). It parses imports with the TypeScript pre-processor and complements, rather than replaces, the ESLint determinism guard. Notable rules:
    - `web` → contracts only;
    - `api` ↛ `domain`;
    - `contracts` stays browser-safe (zod only, no Node built-ins);
    - `@civ/testing` is for tests only.
11. **Strict reads require versioned evolution.** Persisted and exchanged contracts reject unknown fields. Every change, including additive ones, therefore bumps `schemaVersion`/`typeVersion` and rolls out expand → migrate → contract: readers that accept both versions ship before writers emit the new one. The only lenient read is the non-persisted `health-report`, because probes cross build boundaries.
12. **Hostile-input hygiene at the contract layer:**
    - validation issues never echo values or caller-chosen keys;
    - source URLs exclude credentials, IP literals and local names to limit SSRF;
    - operator reason text excludes control and bidi characters;
    - canonicalization has a depth cap.
13. **Test builders live in `@civ/testing`** and construct every value through the production parsers, with deterministic counters.

## Consequences

- Adding a message variant means:
  1. add a definition;
  2. add a fixture and freeze it;
  3. regenerate schema docs.
- Changing a persisted contract means a new version alongside the old one, never an edit.
- Allowing a new edge between workspaces requires editing the policy and recording the reason in an ADR.
- The architecture checker cannot see code outside `src/` (it treats that code as tooling), symlinked directories, or `/// <reference>` directives. Fixture immutability is enforced relative to the manifest in the same tree; a diff against the base branch is not yet a gate.
- The JSON Schemas cannot express cross-field refinements, such as end after start or the allowed review transitions. Those rules exist only in code, and the schemas say so in their descriptions.

## Alternatives considered

- **Protobuf/JSON Schema as the source:** an extra toolchain, and it loses the TypeScript-native refinements.
- **dependency-cruiser:** a new dependency, and the checker needed is small and testable.
- **ESLint `no-restricted-imports` only:** misses `package.json` declarations and relative escapes, and its config per workspace becomes unwieldy.
